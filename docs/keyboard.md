# A keyboard that follows text input

Mobile profile `0.1.0-9` integrates wvkbd `0.20-2` with Omarchy's existing keyboard button. After local PIN enrollment, compatible text fields can show the keyboard automatically and hide it when text input ends. The button remains available for manual control in applications that do not expose compatible text input.

While the trusted PIN-creation surface is open, the desktop keyboard stays hidden in manual mode and its toggle returns `LMI_PIN_SETUP_ACTIVE`. The trusted PIN keypad provides its own input. No owner PIN or acceptance marker is generated by installing this update.

## What changed

The native client listens to Hyprland's lock notifications. It removes its layer when the session locks, refuses show/toggle requests while locked and clears latched modifiers. A keyboard started without `--hidden` during an existing lock also remains unmapped. The compositor continues to enforce the session lock; these keyboard changes do not replace authentication.

The client applies input-method activation at the end of the compositor's event batch. Surrounding-text changes alone do not cancel a deliberate manual hide. Pointer entry initializes the key coordinates so a click need not depend on a previous motion event.

Repeated write/hide checks exposed an outstanding popup frame callback after its surface was destroyed. Hiding now cancels that callback as well as the main surface callback, releases the popup viewport and clears its drawing state before reuse. The corrected package completes the repeated input sequence below.

The service uses native `READY=1` notification. A start request completes after Wayland initialization and the signal channel are ready; the button can immediately request visibility. No extra polling service runs in the normal desktop. An owner-setup success hook refreshes an already-running keyboard after enrollment. That real owner transition is still pending acceptance.

The public enrollment/validation status directories are installed as root-owned `0755` directories. They contain only public status, separately from the existing root-private credential store. The launcher requires a regular root-owned `0644` configured marker and a finished setup service before selecting automatic mode.

## Inherited validation and lmi limits

The keyboard lifecycle (lock-aware hiding, write/hide/show cycling, manual-hide
persistence, modifier latching, native service `READY=1` startup) is inherited
unchanged from the omarchy-apollo integration, where a 19-check
isolated-compositor record covered GTK focus cycles, virtual-pointer text
entry through wvkbd, nested session locks and recovery after unlock. **No lmi
device record exists yet.** The FocalTech touch input, the AMOLED panel and
the real finger path on this device are all untested; nothing here claims
physical typing works on the POCO F2 Pro.

## Reproduce

On the device, as the local desktop account, once the base is installed:

```sh
systemd-run --user --wait --pipe --collect \
  python -I /path/to/omarchy-lmi/tests/check_keyboard_lifecycle.py
```

Optional test dependencies include KWin, a C compiler, `pkg-config`, `wayland-scanner` and the `wayland-protocols` development files. The helper builder downloads one MIT-licensed virtual-pointer protocol from a pinned upstream commit and verifies its SHA-256. Generated protocol code and binaries stay in the private temporary test directory. A candidate executable can be supplied with `--keyboard /absolute/path/to/wvkbd-mobintl`.

Physical finger typing, real owner PIN unlock, enrollment-to-automatic-mode transition, other toolkits, XWayland, Android input, suspend and cold-boot behavior remain pending. These checks establish native GTK input and keyboard lifecycle behavior; they do not establish universal application compatibility or measured battery improvement.
